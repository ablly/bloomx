# 支付适配层与管理员账本

## 背景

BloomX 面向全球用户销售模型 API 能力和积分套餐，需要同时覆盖 Visa、Mastercard、微信支付和支付宝。单一绑定某个支付平台会带来后续迁移风险，也会让订单、积分、退款、订阅和结算状态散落在第三方系统里。

当前判断：

- Stripe 更适合作为首发通道，因为它覆盖银行卡、支付宝和微信支付，生态成熟，适合快速上线全球收款。
- Dodo Payments 适合作为 Merchant of Record 和全球税务/合规备选，后续可作为第二通道或特定市场通道。
- BloomX 必须拥有自己的订单账本、积分账本、Webhook 事件表和管理员对账后台，第三方支付平台只能作为支付执行方，不能成为业务状态唯一来源。

## 目标

- 建立支付平台抽象层，支持 `stripe` 和 `dodo` 两类 provider。
- 首发优先接 Stripe，预留 Dodo Payments 接口和 MCP/文档接入方式。
- 统一订单、订阅、积分、退款、Webhook 和商家结算账本。
- 管理员后台提供支付对账、Webhook 重放、退款复核和账本修正入口。
- 所有支付链路满足生产要求：服务端下单、Webhook 验签、幂等、审计、测试/生产隔离。

## 非目标

- 本 change 不直接接入真实 Stripe 或 Dodo 密钥。
- 本 change 不处理真实商家分账打款。
- 本 change 不跳过管理员后台直接自动结算。
- 本 change 不把支付平台特有字段直接暴露给业务 UI。

## 影响范围

- 支付和积分数据模型
- 管理员后台规划
- Webhook 处理规范
- 工作流和支付平台选择规则
- 后续 Stripe/Dodo 实现任务拆分
