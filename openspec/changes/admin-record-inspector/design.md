## Context

当前管理员后台已经能按集合读取真实记录，但通用表格无法承载生产运营需要的“看一条、判断风险、准备动作”的工作方式。本次先补记录检查面板，保持前端只读，后续再接服务端动作 API。

## Goals / Non-Goals

**Goals:**

- 让管理员在列表中点选记录并查看详情。
- 用户页优先显示身份、余额、验证和登录字段。
- 所有敏感动作只展示计划入口，不从前端直接写数据。

**Non-Goals:**

- 本次不实现角色调整、冻结、积分修正等真实写操作。
- 本次不创建新的后端函数。
- 本次不改变 Firestore rules。

## Decisions

1. **详情面板放在表格右侧。**  
   这样桌面端能形成“列表 + 检查器”的生产后台结构，移动端自然堆叠到表格下方。

2. **动作按钮全部保持禁用。**  
   现阶段宁可显得保守，也不能让前端直接改用户、账本或支付状态。下一步统一接服务端审计动作 API。

3. **字段读取采用容错 key 列表。**  
   用户集合历史字段可能有 `credits_balance` 和 `credits` 两种形态，面板按优先级读取并提供 fallback。

## Risks / Trade-offs

- **真实字段不完整** → 面板显示“未记录”。缓解：后续在数据迁移或 profile 创建函数中统一字段。
- **按钮不可操作会显得半成品** → 这是刻意的安全边界，真实动作必须等服务端审计 API。
