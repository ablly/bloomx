## 背景

管理员后台已经可以把敏感动作写入 `audit_logs`，但上一版只做 dry-run，不会形成“提交请求 -> 审批 -> 执行 -> 审计结果”的生产闭环。商业后台需要把真实修改生产数据的能力收束到服务端，并且每一步都可追踪、可拒绝、可复盘。

## 目标

- 把普通后台动作默认创建为 `pending_approval` 审批请求。
- 在审计页支持对动作请求进行“审批执行”或“拒绝”。
- 服务端执行第一批低风险动作：冻结/解冻用户、提交复核、Webhook/工作流重放排队、导出摘要类动作。
- 角色调整和积分修正必须携带明确参数，否则只允许进入审批请求，不直接执行。
- 每次审批、拒绝和执行结果必须回写 `audit_logs`，包含 actor、reason、beforeSummary、afterSummary 和错误。

## 非目标

- 本次不实现完整退款、结算打款、真实 Stripe/Dodo 支付对象修改。
- 本次不做多人审批、审批矩阵或独立后台角色管理 UI。
- 本次不把管理员密码、支付密钥或工作流密钥写入前端或仓库。
